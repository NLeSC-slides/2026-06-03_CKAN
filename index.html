Datasets & Resources

  • A dataset is a container combining multiple resources (files) under one metadata record
  • Resources can be any format: CSV, GeoJSON, PDF, images, NetCDF, …
  • Example: a research dataset with raw data, a notebook, and a publication PDF — all in one place
  • Each resource has its own metadata: name, format, description

Uploading Data — API

  • Everything in the UI is also available as a REST/JSON API
  • Two-step process:
    package_create → resource_create
  • Authenticate via API token in the Authorization header
  • Scriptable with any HTTP client — curl, Python requests, R, …
  • Enables automated ingestion pipelines and CI/CD workflows

Create Dataset

API_KEY=...
curl -X POST http://localhost:5000/api/3/action/package_create \
  -H "Authorization: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "demo-research-dataset",
    "title": "Demo Research Dataset",
    "notes": "A demo dataset with CSV and GeoJSON.",
    "license_id": "cc-by",
    "owner_org": "demo-organization",
    "tags": [{"name": "demo"}, {"name": "research"}, {"name": "geospatial"}]
  }'

Upload Resource

curl -X POST http://localhost:5000/api/3/action/resource_create \
  -H "Authorization: $API_KEY" \
  -F "package_id=demo-research-dataset" \
  -F "name=Research Stations" \
  -F "format=CSV" \
  -F "upload=@stations.csv"

Uploading Data — GUI

  • Create a dataset via the web interface: fill in metadata, then attach resources
  • Resources can be uploaded as files or linked by URL
  • Drag-and-drop file upload supported
  • Suitable for one-off uploads and less technical users

Metadata

  • Default fields: title, description, tags, license, author, maintainer
  • Fully extensible via ckanext-scheming — define custom fields in YAML
  • Add domain-specific fields: DOI, related publication, data type, embargo date
  • Link datasets to related repositories, code, and papers

Data Previews

Built-in Viewers

  • CSV / tabular — sortable, filterable table (DataTables)
  • GeoJSON — interactive map via ckanext-geoview
  • Images — inline rendering
  • PDF — in-browser viewer
  • Plain text — syntax-highlighted display

Auth & Access Control

Organizations, Roles & Permissions

  • Organizations own datasets
  • Three roles: member (read), editor (edit), admin (manage members)
  • Datasets can be public or private (visible only to organization members)
  • Sysadmins manage the whole instance
  • API token-based authentication for all programmatic access

Federation & Harvesting

Harvesting with ckanext-harvest

  • Pull metadata from remote sources on a schedule
  • Supported protocols: CKAN API, OAI-PMH, DCAT, CSW
  • Enables building aggregator portals on top of distributed repositories
  • Harvested datasets are searchable alongside local datasets
  • Real-world examples
    • National portals aggregating from regional instances
    • Companies aggregating from public datasets

Theming & Customization

Extending CKAN

  • UI customizable via CSS overrides and Jinja2 template overrides
  • No core code changes needed — extensions override templates selectively
  • Organizations and groups can have custom logos and descriptions
  • Plugin interface allows deep customization: custom dataset forms, auth logic, resource controllers
  • Large ecosystem of community extensions

Aim

  • CKAN wants to be a batteries-included data portal — API, previews, auth, federation out of the box
  • Designed to be extended — schemas, plugins, harvesters
  • Used in production at national open data portals and research institutions worldwide
  • Open source, active community, Docker-ready

Challenges

  • Production software vs small deployment
  • Docker works - for vanilla stuff
  • Fancy functionality is not designed for Docker
